What problem does this solve?

A support assistant can sound helpful while making the wrong operational decision. It might route a security issue to billing, skip required human review, recommend a vague next step, or ask a customer to paste a secret.

This suite checks those behaviours separately. It stores every run and case result, then compares a new candidate with the baseline so a reviewer can make a release decision from evidence instead of a few good-looking demos.

Use cases

When this is useful

Before changing a prompt

Run the old and new prompt against the same cases and inspect the exact regressions.

Before switching models

Keep the evaluation contract fixed while the provider or model changes.

For safety requirements

Turn “never request credentials” and “security needs review” into executable checks.

Inside CI

Use deterministic candidates to verify grader behaviour without credentials or provider costs.

How it works

One run, five clear steps

  1. Load the cases.

    Each case defines the customer request, expected category, severity, review requirement, and approved next action.

  2. Run the candidate.

    Use a built-in deterministic profile or explicitly connect an OpenAI model.

  3. Validate the output.

    The response must match a typed schema before it is accepted or graded.

  4. Grade each decision.

    Routing, human review, next-action quality, and secret safety are checked independently.

  5. Save and compare.

    SQLite stores the run and case evidence. The comparison endpoint reports deltas and regressed case IDs.

Release blocked What the reviewer learns

Routing still passes, so a category-only test would approve the change. The independent safety checks show that the critical-case pass rate fell and identify the exact output that caused it. The release is blocked until the candidate recommends safe metadata checks and the approved revocation path.

Architecture

Small enough to inspect

JSON dataset→Candidate adapter→Typed output→Four graders→SQLite ledger→Comparison

app/core.py contains the cases, candidates, sanitization, and graders. app/store.py owns persistent run evidence. app/main.py exposes the API and optional provider boundary.

Get started

Run it in a few minutes

Terminalquick start
$ git clone https://github.com/Emmanuelasika/support-ai-evaluation-suite.git
$ cd support-ai-evaluation-suite
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -e ".[dev]"
$ uvicorn app.main:app --reload

Open http://localhost:8000 for the workbench or /docs for the API reference.

What it does not claim

This is a reference implementation, not a hosted evaluation platform. Production use still needs authenticated projects, encrypted traces, dataset governance, calibrated human labels, cost tracking, retention controls, and protected release approvals. Eight cases demonstrate the workflow; they do not represent complete risk coverage.
